PASO A PASO

Tu aplicación en línea.

Configura MongoDB Atlas para guardar los invitados y Render para publicar la aplicación. Necesitas cuentas en GitHub, MongoDB Atlas y Render, y Node.js 22 o superior en tu computador.

01 · Preparar el código02 · Crear la base de datos03 · Crear el administrador04 · Publicar en Render05 · Autorizar la conexión06 · Probar el evento

01 · Clona y prepara el código fuente

Desde GitHub clona el repositorio del código fuente en tu computador y abre su carpeta principal. El repositorio del fuente es generador-QR-bienvenida-. El repositorio de despliegue contiene solo el paquete generado.

git clone https://github.com/DevsFelipe/generador-QR-bienvenida-.git
cd generador-QR-bienvenida-
npm ci

Crea tu configuración local copiando reception/.env.example a reception/.env. No sobrescribas un archivo existente. Completarás la conexión en el paso 03. El ejemplo no contiene claves; tus contraseñas deben permanecer fuera de Git.

No publiques archivos .env, acceso-*.txt, planillas de invitados ni respaldos. El Git del fuente excluye outputs/, que contiene el resultado generado y puede tener su propio repositorio.

02 · Crea la base en MongoDB Atlas

  1. Crea un proyecto y un clúster. Para una prueba puedes elegir la opción Free disponible.
  2. En Database & Network Access → Database Users, crea un usuario con contraseña propia y permiso readWrite únicamente sobre la base invitaciones. Este usuario conecta la aplicación; es distinto del administrador del evento.
  3. En IP Access List, agrega tu IP actual para configurar y probar desde tu computador. Espera hasta que aparezca activa.
  4. En el clúster, abre Connect → Drivers and Client Libraries y elige JavaScript / Node.js. Copia la cadena de conexión y sustituye la contraseña. Si contiene caracteres especiales, codifícalos para una URL.

La base y sus colecciones se crean al utilizar la aplicación. Sigue la documentación oficial de conexión de Atlas.

03 · Crea tu administrador

En tu copia local crea reception/.env con estos valores de ejemplo, reemplazando usuario, contraseña y clúster por los tuyos:

RECEPTION_MONGODB_URI=mongodb+srv://USUARIO:CONTRASENA@TU-CLUSTER.mongodb.net/?authSource=admin
RECEPTION_MONGODB_DB=invitaciones
RECEPTION_ORIGIN=http://127.0.0.1:3220

Desde la carpeta principal ejecuta:

npm run reception:user -- --username mi_admin --admin

La contraseña generada queda en reception/acceso-mi_admin.txt. Guárdala de forma segura. El usuario se registra en MongoDB y servirá también en Render si conectas la misma base. No ejecutes de nuevo el alta de un usuario ya existente.

Prueba localmente con npm start y abre http://127.0.0.1:3220. Si usas una base antigua, respáldala y revisa la migración del proyecto antes de actualizarla.

04 · Genera el paquete y publica en Render

Después de configurar y probar localmente, vuelve a la raíz del código fuente y genera el paquete:

npm run package:render

En una instalación nueva obtendrás outputs/recepcion-render. El generador copia solo el código necesario. Si ya existe un Git de despliegue con su paquete anidado, lo actualiza conservando su estructura; revisa la carpeta final que informa el comando.

Para un paquete nuevo sin Git, crea un repositorio vacío en GitHub y ejecuta:

cd outputs/recepcion-render
git init -b main
git add .
git commit -m "Publicar aplicación de recepción"
git remote add origin URL_DE_TU_REPOSITORIO_DE_DESPLIEGUE
git push -u origin main

Reemplaza la URL por la de tu repositorio. Si ya tienes el Git de despliegue, revisa los cambios y haz commit y push sobre su rama actual; no lo reinicialices. En futuras ediciones modifica el fuente, vuelve a generar y publica el paquete actualizado.

  1. En Render selecciona New → Web Service, conecta GitHub y elige tu repositorio y la rama que publicarás.
  2. Selecciona Docker. Si package.json está en la raíz del repositorio, deja Root Directory vacío. Si está dentro de recepcion-render, indica esa carpeta.
  3. Dentro de esa carpeta, selecciona Dockerfile Path: reception/Dockerfile y usa la misma carpeta raíz como contexto de construcción. No repitas el prefijo de la carpeta en ambos campos.
  4. Elige el plan disponible que corresponda a tu prueba. Docker utiliza el comando del Dockerfile; no necesitas un Build Command ni Start Command de Node.
  5. Agrega las siguientes Environment Variables en Render, sin subirlas a GitHub:
VariableValor
NODE_ENVproduction
RECEPTION_HOST0.0.0.0
RECEPTION_TRUST_PROXYtrue
RECEPTION_MONGODB_DBinvitaciones
RECEPTION_MONGODB_URITu cadena privada de Atlas

Configura el health check como /healthz y pulsa Deploy Web Service. Render proporciona PORT y su dirección pública automáticamente; no fijes el puerto local. La aplicación usa RENDER_EXTERNAL_URL si no defines RECEPTION_ORIGIN. Si usas un dominio propio, define esta última con su URL HTTPS exacta, sin barra final.

Consulta Docker en Render para las opciones vigentes.

05 · Autoriza a Render en Atlas

  1. En tu servicio de Render abre Connect → Outbound y copia todos los rangos de salida que muestra tu servicio.
  2. En Atlas abre Database & Network Access → IP Access List → Add IP Address y agrega cada rango por separado.
  3. Espera a que todos aparezcan activos y vuelve a probar el acceso. Usa los rangos de tu servicio; no copies los de otro despliegue.

Un despliegue con estado Live confirma que el servidor arrancó. Para verificar la conexión real a MongoDB debes iniciar sesión y guardar un evento.

06 · Prueba el recorrido completo

  1. Abre la URL HTTPS del servicio e ingresa con el administrador que creaste.
  2. Crea un evento y carga un Excel con encabezados: nombre | rut | mesa | menu. Correo e institución son opcionales.
  3. Revisa las columnas y confirma la importación. Usa datos ficticios para las primeras pruebas.
  4. Abre la recepción y muestra el QR desde la aplicación publicada. Así el enlace apuntará a Render y podrá abrirse desde un teléfono.
  5. Escanea el QR e ingresa un RUT de prueba. Comprueba que aparecen mesa y menú y que la administración refleja la asistencia. Repetir la consulta conserva el primer ingreso.

Si no puedes ingresar: revisa la URI, la contraseña del usuario de base de datos y los rangos activos en Atlas. Si el evento no acepta llegadas: comprueba que su recepción esté abierta y que el invitado tenga una asignación completa.

El servicio gratuito de Render entra en reposo tras 15 minutos sin tráfico y la siguiente visita puede tardar en reactivarlo. Los datos deben persistir en MongoDB, porque el disco local del servicio no es permanente. Revisa los límites vigentes y prueba con un teléfono antes del evento.
